Big QYL - UI Automation build (deploy)

WHAT CHANGED
  The agent now drives real UI controls with Windows UI Automation (the
  `uiautomation` library), clicked with the human-like mouse - no hardcoded
  pixel positions. Every control has a fallback, so a missing one never stops
  a run.

  - New modules: ui_find.py (control lookup + human click) and calc_nav.py.
  - Calc: Name Box and sheet tabs are the REAL controls. Cells are now CLICKED
    with the mouse when on screen (found by UIA hit-testing, no pixels); a cell
    that is scrolled out of view or hidden still goes via the Name Box.
  - Writer title: clicks the real Bold + Font Size toolbar controls
    (fallback: Ctrl+1 / Ctrl+0 Heading/Body styles).
  - Window close: clicks the real title-bar Close button (fallback: WM_CLOSE).
  - Chrome: address bar clicked by name; closes via the caption Close button;
    NEW live-data actions - reads the Bitcoin price from the CoinGecko row,
    clicks the Bitcoin row to open its page, then goes back.
  - Desktop: the spreadsheet is opened by double-clicking its real icon.

REQUIRED LIBRARIES IN THE VM (request via FTP/SMB if missing)
  uiautomation      -> clicking real controls (import check: py -c "import uiautomation")
  pyautogui         -> keyboard / fallback input
  pywinauto is NOT needed.
  If uiautomation is absent, the agent still runs on the fallback paths.

HOW TO DEPLOY
  1. Take a Proxmox snapshot first (e.g. "before-uia-build").
  2. Copy deploy_to_vm.py into the VM folder that holds orchestrator.py and
     "Profit and Loss Statement.ods".
  3. In that folder run:  py deploy_to_vm.py
     It overwrites the 15 agent .py files (incl. diag_uia.py) and verifies each
     one's SHA-256. It does NOT touch the .ods workbook.
  4. Run the agent from a DESKTOP SHORTCUT to pythonw.exe (so ParentImage is
     explorer.exe), pointing at orchestrator.py in that folder.

BEFORE THE DEMO - CHECK IN THE VM
  - py -c "import uiautomation" prints nothing (ok) - not an error.
  - The desktop icon is named "Profit and Loss Statement - Shortcut"
    (ui_find matches on "Profit and Loss Statement"). If yours differs, edit
    SPREADSHEET_ICON_NAME in spreadsheet_part1.py.
  - Do ONE full test run and review the Sysmon Event ID 1 ParentImage values.

WHAT WAS FIXED IN THIS BUILD
  The previous build still fell back to shortcuts for Bold / Font Size / Name
  Box / cells. Causes, all fixed:
    1. Wrong control type: OpenOffice exposes the Name Box and Font Size as
       COMBO boxes, but the code only searched for Edit controls, so they were
       never found. Lookups now accept ComboBox/Edit (Bold: Button/CheckBox),
       match names loosely ("Bold (Ctrl+B)" == "Bold") and click the combo's
       text field, not its drop-down arrow.
    2. The old note was wrong: uiautomation's search is NOT native FindFirst,
       it walks the WHOLE tree in Python, including Writer's text and Calc's
       cell grid, and only checks its timeout after a full pass. OpenOffice
       lookups now use a bounded walk (ui_find.find_office) that skips the
       document / grid and stops after a few seconds.
    3. Cells were never clicked (always the Name Box). calc_nav.go_to_cell now
       clicks the real cell when visible.
  Each OpenOffice lookup prints "[uia] ... found / NOT found" (DEBUG = True).

30-SECOND PRE-CHECK (run this first)
  With Writer AND Calc open, run (no clicking needed):
      "C:\\...\\pythonw.exe" diag_uia.py
      type uia_diag.txt
  Every line should say "found" (Bold, Font Size, Name Box, Summary, Salary) and
  "cell A1/E4/F19: on screen". If any says NOT found, send me uia_diag.txt: it
  includes the toolbar tree with the real names / types to match on.

NOTES
  - All changes were tested against a MOCKED accessibility tree on a dev
    machine (clicks land on the right controls, fallbacks trigger correctly).
    They have NOT yet run on the VM - run diag_uia.py, then a full test run.
  - OpenOffice exposes its toolbar / document / cells ONLY if Windows reports
    a screen reader when OpenOffice STARTS. Without it UIA sees just the title
    bar + Minimize/Restore/Close ("walked 6 controls"). The orchestrator now
    sets that flag at session start (not saved; reverts at logoff) and clears
    it at the end. Close the OpenOffice Quickstarter (tray icon) before a run,
    or the already-running soffice keeps its old state.
  - To test without a full run: diag_uia.py --enable, close ALL OpenOffice
    windows + Quickstarter, reopen Writer + Calc, run diag_uia.py again.
    If it still sees only the frame, also turn on Tools > Options >
    OpenOffice > Accessibility > "Support assistive technology tools" (if
    present), restart OpenOffice, and re-run diag_uia.py.
